# Agent Delegation Contract

## Summary

위임 계약은 에이전트가 다른 에이전트에게 일을 넘길 때 **세 가지를 미리 못 박는** 규약이다 —
넘기는 입력의 형식, 돌려받을 산출물의 형식, 그리고 **실패로 판정하는 조건**. 역할을 나누는
것([[wiki/multi-agent-orchestration|Multi-Agent Orchestration]])만으로는 부족하다는 관찰에서
나왔다. 회고 문서가 도입 초기 2주 동안 가장 많이 깨진 지점으로 지목한 것은 모델의 능력이
아니라 "에이전트 사이에 넘어가는 것이 무엇인지 합의되지 않은 것"이었다.

세 번째 항목이 이 패턴의 무게중심이다. **실패 조건이 없으면 하위 에이전트는 무엇이든
그럴듯한 결과를 만들어 돌려주고, 상위는 그것을 검증 없이 받는다.**

## Details

### 세 항목

| 항목 | 정하는 것 | 없을 때의 실패 |
| --- | --- | --- |
| 입력 형식 | 하위에게 넘기는 데이터의 모양 | 하위가 원문을 다시 읽어 상위 작업을 중복 수행 |
| 산출물 형식 | 돌려받을 결과의 모양 | 상위가 통합하지 못하거나 재가공에 시간을 쓴다 |
| 실패 판정 | 무엇을 실패로 볼지 | 그럴듯한 산출물이 검증 없이 통과한다 |

입력·산출물 형식만 정하고 실패 조건을 빠뜨리는 것이 전형적인 절반짜리 적용이다. 앞의 둘은
산출물이 어긋나면 눈에 띄지만, 실패 판정의 부재는 **성공처럼 보이는 실패**를 만들어 내므로
드러나지 않는다.

### 역할별 계약의 예 (설계 회의 정리본)

회고 문서의 첨부에 실린 역할 배치안이다. 각 역할에 산출물과 실패 판정이 짝으로 붙어 있는
형태가 이 패턴의 구체적인 모습이다.

| 역할 | 담당 범위 | 산출물 | 실패 판정 |
| --- | --- | --- | --- |
| 오케스트레이터 | 작업 분해·위임·통합 | 작업 계획, 최종 보고 | 하위 산출물 통합 불가 |
| 조사 | 문서·코드 탐색 | 근거 목록(출처 포함) | 출처 없는 주장 포함 |
| 구현 | 코드 변경 | diff, 테스트 결과 | 테스트 미실행 또는 실패 |
| 검토 | 적대적 반증 | 반증 항목 목록 | 지적 0건 + 근거 없음 |

검토 역할의 실패 판정("지적 0건 + 근거 없음")이 특히 이 패턴의 성격을 보여준다. 산출물이
비어 있는 것 자체는 실패가 아니고, **비어 있으면서 왜 비었는지 근거가 없을 때** 실패다.

### 핸드오프 실패의 회수

계약이 실패를 **판정**하고 나면 그 다음이 회수 전략이다. 회고 문서의 결론은 단순 재시도가
대개 무의미하다는 것이다 — 재시도 전에 실패 원인을 입력에 반영하지 않으면 같은 결과가 나온다.

```
하위 실패 → 원인을 입력으로 되먹임 → 1회만 재시도 → 그래도 실패하면 사람에게 올린다
```

재시도 상한을 1회로 둔 것은 회의에서 합의된 값이지만 미결 안건으로도 남아 있다 — "실패 회수
재시도 상한 1회 유지 여부 — 4주 운영 후 재검토". (needs-update: 재검토 결과는 원문에 없다.)

### 하네스 지침 쪽의 짝

같은 조직의 하네스 운영 지침은 위임 계약 서식을 별도 문서로 분리해 두고 지침 본문에서는
포인터만 둔다(§ 6 관련 문서). 지침 파일의 분량 예산을 지키는 방식이며,
[[wiki/agent-instruction-files|Agent Instruction Files]] § 이식성이 다루는 포인터 방식의
약점을 그대로 물려받는다.
