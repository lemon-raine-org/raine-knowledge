# Agent Context Optimization

## Summary

컨텍스트 최적화는 AI에게 코드베이스를 자유 탐색하게 두는 대신, **전처리 스크립트가 먼저
실행되어 필요한 메타데이터만 정제해 넘기는** 패턴이다. 탐색 단계(tool call)를 없애 응답을
빠르게 만들고, 무관한 코드를 참조해 생기는 환각(hallucination)을 줄인다.

## Details

### 문제 — 자율 탐색의 비용

Skills를 고도화하면 'AI의 자율 탐색으로 인한 컨텍스트 낭비'에 부딪힌다. 관련 파일 탐색을
전적으로 맡기면 불필요한 내부 로직과 import 문까지 모두 읽어 컨텍스트 윈도우를 과도하게
소진한다. 탐색이 길어져 응답이 느려지고, 잘못된 코드를 참고할 확률도 같이 올라간다.

### 패턴 — AS-IS / TO-BE

```
AS-IS: 사용자 요청
  → AI가 프로젝트 내 관련 파일을 직접 탐색 (반복적인 Tool Call 발생)
  → 목적과 무관한 내부 구현 로직 및 설정 파일까지 컨텍스트에 포함
  → 코드 생성

TO-BE: 사용자 요청
  → 전처리 스크립트가 실행되어 코드 생성에 필요한 메타데이터만 추출
  → 정제된 요약 데이터(JSON)를 AI에게 전달
  → 코드 생성
```

AS-IS에서 AI가 읽는 것은 `axiosInstance` import, `logger.info`, `handleError` 같은 구현
디테일까지 포함한 원본 클래스 전문과 수백 줄짜리 `queryKeys.ts`다. TO-BE에서 넘어가는 것은
훅 생성에 실제로 필요한 네 개 필드뿐이다.

```json
{
  "endpoint": "GET /users/:id",
  "queryKey": "queryKeys.user(id)",
  "apiMethod": "UserAPI.getUser",
  "params": { "id": "string" }
}
```

### 구현 방식

전처리는 주로 Node.js 스크립트로 구성했다. 파일 시스템을 순회하며 정규식으로 클래스명과
메서드명 같은 메타데이터만 뽑거나, `openapi-typescript` 같은 도구로 API 명세를 타입 정의
파일로 변환한 뒤 정제된 데이터만 컨텍스트에 넣는다. 원문의 슈도코드는 `.ts` 파일을 훑어
`class (\w+)`와 `async (\w+)\(` 패턴으로 `{ file, className, methods }`만 수집하는
형태다 — import 문과 에러 처리는 그대로 버려진다.

### 측정 결과

5개 도메인을 대상으로 자율 탐색 방식을 스크립트 요약 방식으로 바꿔 측정한 결과다.

| 도메인 규모 | AI 자율 탐색 | 스크립트 요약 | 절감률 | 호출 횟수 |
| --- | --- | --- | --- | --- |
| 대규모 (API 11개) | 41,944 bytes | 1,763 bytes | 95.8% | 4회 → 1회 |
| 중규모 (API 4개) | 29,386 bytes | 668 bytes | 97.7% | 4회 → 1회 |
| 소규모 (API 2개) | 9,749 bytes | 539 bytes | 94.5% | 4회 → 1회 |

평균 96.5% 절감, 1회 작업당 약 6,800 토큰 절감으로 환산된다.

**수치 해석 주의** — 원문이 직접 밝힌 한계다. 토큰 절감량은 실측이 아니라 OpenAI 문서의
"영어 텍스트 기준 1 토큰 ≈ 4 bytes"를 적용한 환산 추정치이며, 한글/영문 코드 비율과 모델
토크나이저에 따라 달라진다. 바이트 절감률은 특정 프로젝트 구조에서 나온 값이라 그대로
일반화할 수 없다. (needs-update: 다른 코드베이스에서의 재측정치 없음.)

### 진짜 수확

원문이 가장 큰 성과로 꼽는 것은 비용 절감이 아니라 컨텍스트 최적화 자체다. 핵심 메타데이터만
넘김으로써 AI가 불필요한 코드를 탐색하다 길을 잃는 환각 문제를 예방하고, 일관된 결과물을
안정적으로 얻게 된다.

### 전처리 계약 — 출력 형식이 바뀌면 소비자도 같은 커밋에서 고친다

운영 지침 사례는 이 패턴을 두 줄의 규칙으로 고정한다.

1. 원본 파일을 통째로 넘기지 않는다. 판단에 필요한 메타데이터만 추출해 넘긴다.
2. 전처리 스크립트의 출력 형식이 바뀌면 이를 소비하는 워크플로를 **같은 커밋에서 함께**
   고친다.

두 번째가 이 패턴의 상시 운영 비용이다. 전처리와 소비자는 문서화되지 않은 스키마로 묶여
있는데, 불일치가 예외나 오류로 드러나지 않는다 — **에이전트가 조용히 빈 값을 채우는 형태로
나타나 발견이 늦다.** 사람이 읽는 코드와 달리 빠진 필드를 모델이 그럴듯하게 메우기 때문이다.
같은 실패 모드를 위임 경계에서 막는 장치가
[[wiki/agent-delegation-contract|Agent Delegation Contract]]의 '실패 판정 조건'이다.

(근거 문서는 검증용 가상 샘플임을 스스로 밝힌다 — 규칙의 형태만 인용한다.)
